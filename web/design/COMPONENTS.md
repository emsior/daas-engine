# Komponenty kokpitu (`web/src/components/`)

Wszystkie używają klas z design systemu (`components.css`) i `app.css`; zero `style=""`. Teksty (etykiety, komunikaty) przekazuje wywołujący albo pochodzą ze słowników `src/i18n`. Stany loading/error/empty/success dla danych z API zapewnia `QueryState`.

## Wzorce użycia

```tsx
<Field id="email" label="Adres e-mail" hint="Np. imie@firma.pl" error={errors.email} required>
  {(control) => <Input {...control} type="email" />}
</Field>

<QueryState query={runs} loadingLabel="Ładowanie…" errorTitle="Nie udało się pobrać raportów"
            isEmpty={(d) => d.length === 0} empty={<EmptyState />}>
  {(runs) => <Archive runs={runs} />}
</QueryState>
```

Formularze: walidacja po wysłaniu, błędy przy polu i w `ErrorSummary` (fokus), wpisy użytkownika zachowane, błąd nie znika sam.

## Uzupełnienia design systemu (`src/styles/app.css`)

`app-header`/`app-nav`/`app-footer` (ramka aplikacji), `.check` (pole wyboru), `fieldset.fieldset`, `.steps` (etapy kreatora), `.dialog*` (okno modalne), `.sort-button`, `.row-details`, `.hash-block`, `.verify-result`, `.kpi-row`, `.view`, `.view-columns`, `.btn[aria-pressed="true"]`. Wszystko z tokenów semantic/component; plik importowany do warstwy `components` przez `globals.css`.
